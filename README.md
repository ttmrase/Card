# カードフォージ (CardForge)

プレイヤーが自分でカードを作り、そのカードで遊べる Android 用カードゲームアプリ。
属性・種族・カテゴリといったカードの構成要素そのものから、効果テキストの中身まで、
すべてアプリ内で作成・編集できる。

## APK の入手

このリポジトリには GitHub Actions のワークフロー (`.github/workflows/android.yml`) が
入っている。ブランチに push すると自動でビルドが走り、Actions の実行ページの
**Artifacts** から `cardforge-apk`（`app-debug.apk` と `app-release.apk`）を
ダウンロードできる。`app-debug.apk` をそのまま端末に入れれば動く。

手元でビルドする場合は Android SDK を入れて次を実行する。

```bash
./gradlew assembleDebug        # app/build/outputs/apk/debug/app-debug.apk
./gradlew test                 # ルールとカードテキストのテスト
```

必要環境: JDK 17、Android SDK (compileSdk 34)。対応端末は Android 8.0 (API 26) 以上。

変更内容と不具合の修正履歴は [CHANGELOG.md](CHANGELOG.md) にまとめています。

## ゲームのルール

- お互いのライフは **8000** ポイント。先に 0 になった方が負け。
- **相手フィールドにモンスターがいる限り、プレイヤーへの直接攻撃はできない。**
- 通常召喚のリリース（生け贄）は、**レベル4以下は不要／5〜6は1体／7以上は2体**。
  通常召喚（セット含む）は1ターンに1度。
- **魔法カード**は自分のターンのメインフェイズにのみ発動できる。
  魔法・罠ゾーンに伏せたあとでも、自分のターンなら発動できる。
- **罠カード**は伏せたターンには発動できない。
  次のターン以降は、相手ターン・自分ターンを問わず発動できる。
- 伏せ罠は、相手の「カードの発動」「召喚」「攻撃宣言」に対して割り込める。
  無効化する効果を持つ罠なら、それらを無効にして破壊する。
- フェイズはドロー → メイン1 → バトル → メイン2 → エンド。最初のターンにバトルフェイズは無い。
- エンドフェイズに手札が6枚を超えていたら、超えた分を捨てる。
- デッキが尽きた状態でドローするプレイヤーは敗北する。

対戦形式は **AI との対戦**と、1台の端末を回して遊ぶ **2人交代（ホットシート）** の2つ。

## カードの作り方

カードは3種類。

| 種類 | 持つ要素 |
| --- | --- |
| モンスター | レベル / 属性 / 種族 / カテゴリ / 攻撃力 / 守備力 |
| 魔法 | カテゴリ（魔法・罠ゾーンで使用、自分ターンのみ） |
| 罠 | カテゴリ（魔法・罠ゾーンで使用、伏せた次のターン以降） |

カード名とイラスト（端末から選択）は自由に設定できる。取り込んだ画像はアプリ内部に
コピーされるので、元の画像を消してもカードのイラストは失われない。
画像を選ぶと切り抜き画面が開くので、ドラッグとピンチでカードのイラスト枠（3:4）に
収める。あとから「切り抜き」ボタンでやり直せる。

属性・種族・カテゴリは、カード作成画面の各欄の横のボタンからその場で
追加・名前変更・削除ができる（ホームの「属性・種族・カテゴリ」からも同じことができる）。

### 効果テキストの自由記述

効果を持つカードは、**【場所】【条件】【コスト】【制限】【発動後】【効果】** の要素を持つ。
モンスター・魔法・罠のいずれも同じ書式で書く。

- **場所** … そのカードを発動できる場所（手札／フィールド／墓地）。
  省略した場合は「フィールドで発動」になる。
  魔法カードの「フィールドで発動」は、手札から魔法・罠ゾーンに出して発動する場合と、
  伏せてあるカードを表にして発動する場合の両方を含む。
  【場所】に『手札』と書いた場合だけ、手札に置いたまま発動する。
  罠カードは必ずセットしてから発動する（【場所】に『手札』と書いた罠を除く）。
- **条件** … 発動に必要な状況。省略するとどんな状況でも発動できる。
  「〜が存在する」のような状態、「相手のモンスターが特殊召喚された場合」のような
  **出来事**、「エンドフェイズである」のような**フェイズ**が書ける。
  出来事を書いた効果は、それが起きたときに発動する誘発効果になり、手動では発動できない。
  フェイズを指定すると、そのフェイズが来たときに発動するか確認が出る
  （エンドフェイズのように操作の手が無いフェイズでも使える）。
- **コスト** … 発動に必要な支払い。省略するとノーコストで発動できる。
  効果と同じ対象指定が使えるので、「自分の墓地のカード2枚をデッキの一番下に戻す」
  のようなコストも書ける。
- **制限** … 1ターンに発動できる回数。後述。省略すると回数制限は無い。
- **発動後** … 発動して解決したあと、そのカードをどうするか。後述。
  省略した場合、魔法・罠は「墓地へ送る」、モンスターは「そのまま残す」。
- **効果** … 実際に起こること。

ひとつの効果の中に「〜し、その後〜する」と複数の処理を並べた場合、
**書いてある順に最後まで処理できる**ときだけ発動できる。
前の処理で動いたカードは差し引いて数えるので、
「相手モンスター1体を破壊し、その後1体を除外する」は相手に2体必要になる。

効果は ①②③… と区切って、1枚のカードに複数持たせられる。
**効果番号より前**に書いた【場所】【条件】【コスト】【制限】【発動後】はそのカードの
全ての効果に掛かり、**効果番号の直後**に書いたものはその番号の効果にだけ掛かる。

効果の1文は「主語・目的語・修飾語・述語」を選択肢から選んで組み立てる。

```
【誰の】【どの領域の】【どんな条件のカード】【何枚】を【どう選んで】【どうする】
   相手     フィールドの   闇属性モンスター     1体      選んで      破壊する
```

選べる述語は、破壊 / 除外 / 手札に加える / 墓地へ送る / デッキに戻す / 特殊召喚 /
攻撃力・守備力の変化 / 表示形式の変更 / ドロー / ダメージ / ライフ回復 /
手札を捨てさせる / デッキから墓地へ送る / 魔法・罠ゾーンにセットする /
魔法・罠ゾーンに表側で置く / そのカードを発動する / 耐性を与える /
攻撃できなくする / 発動の無効化。

絞り込みの条件には、カードの種類・属性・種族・**カテゴリ**・レベル・攻撃力・守備力・
表示形式・カード名が使える。組み立てている途中の文はその場で日本語に整形して表示される。

### 【発動後】

発動して解決したあと、そのカードをどう扱うかを選ぶ。魔法・罠カードに適用される。

| 指定 | 挙動 |
| --- | --- |
| 墓地へ送る | 通常魔法・通常罠のように使い切る |
| そのまま残す | 永続魔法のようにその場に残る |
| 除外する | 発動後そのまま除外される |
| 手札に戻す | 発動後に手札へ戻る |
| デッキに戻す | 発動後にデッキの一番上へ戻る |

省略した場合、魔法・罠は「墓地へ送る」、モンスターは「そのまま残す」。
既定どおりのときはカードテキストに書かれない。
その場に残したカードは、【制限】に掛からない限り繰り返し発動できる。

### 手札誘発モンスター

手札で発動するモンスターは、カードが墓地へ行くタイミングを2通りから選べる。

| 書き方 | いつ墓地へ行くか |
| --- | --- |
| 【コスト】このカードを墓地へ送る | 発動と同時。無効にされても手札には戻らない |
| 【発動後】墓地へ送る | 効果の解決後。発動時点ではまだ手札にある |

### 数値の指定

攻撃力・守備力の変化、ダメージ、ライフ回復の数値は、固定値のほかに
**「条件を満たすカードの枚数 × 係数（＋固定値）」** で決められる。
数える対象は、いつもの対象指定で指定する。

```
①：相手に自分の墓地のモンスターの数×200ポイントのダメージを与える。
```

### 効果テキストの手直し

自動で組み立てた文の助詞などが不自然なときは、カード編集画面の
「効果テキストの手直し」から表示だけを書き換えられる。
ゲーム中の動作は効果データのままで変わらない。
「自動生成し直す」で作り直し、「手直しをやめる」で自動生成に戻せる。

### 発動タイプ

効果ごとに3つから選ぶ。

| 発動タイプ | 挙動 |
| --- | --- |
| 発動できる（任意） | 発動するか確認する。テキストの語尾は「〜できる」 |
| 発動する（強制） | 自動で発動する。語尾は「〜する」 |
| **発動時** | そのカード自体を発動したときにだけ処理される |
| **永続** | 発動しない。そのカードが【場所】にある限りずっと適用される |

### カードの発動と、効果の発動

発動時処理か永続の効果を持つ魔法・罠は、効果を選ばずに
**カードそのものを発動**してフィールドに出せる（永続魔法など）。
発動できる効果も持っている場合は、どちらを行うか選ぶ。
表側で場に出ているカードは発動済みなので、もう一度は発動できない。

```
【発動後】そのまま残す
①：このカードの発動時に、自分はカードを1枚ドローする。
②：このカードがフィールドに存在する限り、
　　自分モンスターゾーンの全ての「アララギ」モンスターの攻撃力は500アップする。
```

### 永続効果

永続効果も専用の欄ではなく、**発動タイプを「永続」にした効果**として書く。
【場所】【条件】【効果】といった部品はそのまま使える。

```
①：このカードがフィールドに存在する限り、
　　自分モンスターゾーンの全ての「アララギ」モンスターの攻撃力は500アップする。
```

- 【場所】を墓地にすれば「墓地に存在する限り」の永続効果になる。
- 【条件】を付ければ「自分のライフが2000以下の間だけ」のように、
  状況によって効いたり切れたりする永続効果になる。
- 1枚のカードに、永続の効果と発動する効果を①②として並べられる。

永続向きの述語として **耐性を与える**（相手の効果を受けない／戦闘では破壊されない／
効果では破壊されない）と **攻撃できなくする** がある。
これらを発動する効果に書くと、**そのターンの間だけ**適用される。

「相手の効果を受けない」カードは、相手の効果の対象そのものに選べなくなる。
攻守の増減は戦闘計算・効果の絞り込み・画面表示のすべてに反映される。

対象指定には **「この効果を持つカード自身」** を選べる。
永続効果だけでなく、「このカードを破壊する」のような発動する効果でも使える。

### 【制限】

「1ターンに何度まで発動できるか」を、数える単位とあわせて指定する。

| 単位 | 数え方 |
| --- | --- |
| このカード | 場にあるその1枚だけを数える |
| 同名カード | 同じ名前のカードをまとめて数える |
| カテゴリ | 指定したカテゴリのカードをまとめて数える |

効果番号より前に置いた制限はそのカードの全ての効果をまとめて数え、
効果番号の直後に置いた制限はその番号の効果だけを数える。

> 例：【制限】「アララギ」カードを含めて1ターンに1度しか発動できない
> → 「アララギ」カードなら別名のカードでも、1ターンに合計1回しか発動できない。

### カテゴリ

すべてのカードに自由な「カテゴリ」を付けられる。カテゴリは効果テキストから参照できるので、
テーマデッキを丸ごと自作できる。

> 例：カテゴリを「アララギ」にしておくと、
> 『自分のデッキの「アララギ」モンスター1体を選んで自分のモンスターゾーンに
> 表側攻撃表示で特殊召喚する。』という効果が書ける。

属性・種族・カテゴリは「属性・種族・カテゴリ」画面でいつでも追加・改名・削除できる。
削除した場合、それを参照していたカードからは自動的に外れる。

## カードとデッキの受け渡し

カード一覧の右上から、全カードとデッキを JSON ファイルとして書き出せる。
デッキ一覧では、デッキとそのデッキが使っているカードだけを書き出せる。
イラストもファイルに埋め込まれるので、1ファイルで他の端末に渡せる。

書き出すときも取り込むときも、カードとデッキをチェックして選べる。
デッキを選ぶと、そのデッキが使っているカードも自動で選ばれる。
取り込みはファイルの中身を一覧で見てから選べ、長押しで効果も確認できる。

取り込むときは、属性・種族・カテゴリを**名前**で突き合わせて既存のものを使い回し、
カードの中の参照もまとめて貼り替える。カードは ID で上書きするので、
同じファイルを2回取り込んでも増えない。

## 操作

カード一覧・デッキ編集・デュエル中の手札やフィールド、
そしてデッキをサーチしているときの選択画面では、
**長押し**するとカードのイラストと効果テキストを確認できる。

## 構成

```
app/src/main/java/com/cardforge/
├── model/      カード・効果 DSL のデータ定義（kotlinx.serialization でJSON化）
│   ├── Enums.kt      プレイヤー・領域・比較・表示形式などの選択肢
│   ├── Effect.kt     場所・条件・コスト・効果と、対象指定 (CardScope)
│   └── Library.kt    カード / デッキ / マスターデータ
├── text/       構造化された効果データを日本語のカードテキストに整形
├── data/       JSON 永続化、イラストの取り込み、書き出し／取り込み、初期データ
├── game/       デュエルのルール処理
│   ├── GameModels.kt 盤面の状態
│   ├── GameEngine.kt 召喚・戦闘・効果解決・ターン進行
│   ├── Interaction.kt プレイヤーへの問い合わせ口
│   └── Ai.kt         AI の思考
└── ui/         Jetpack Compose の画面
```

エンジンがプレイヤーに選択を求めるときは `Interaction` 越しに suspend 関数で待つ。
UI はそこにダイアログを出し、AI は自動で答える。どちらも同じルール処理を通る。

## テスト

`app/src/test/` にルールとカードテキストのテストがある。

```bash
./gradlew test
```

- `GameRulesTest` … ライフ8000、リリース数、直接攻撃の制限、戦闘ダメージ計算、
  罠の発動タイミングとセット必須のルール、魔法の発動タイミング、
  手札・フィールド・墓地それぞれからの発動、場所・条件・コストによる発動制限、
  【発動後】の各挙動、【制限】の3つの単位と枠の共有範囲、
  コスト不成立時の巻き戻し、カテゴリ指定、
  ライフ0とデッキ切れによる決着。
- `CardTextTest` … 効果テキストの整形と JSON の往復。
- `DuelSimulationTest` … AI 同士のデュエルを通しで回し、盤面が壊れないことと、
  【制限】の枠が上限を超えて使われないことを毎ターン確認する。
